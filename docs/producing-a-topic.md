# Producing a learning block

The whole path from a written script to a published video and practice set, in order. Each step
links to the document with the details. A learning block is a topic, or one subtopic of a topic
that has them ([course-design.md](course-design.md)).

```
1 script ─► 2 script.json ─► 3 audio ─► 4 video.html ─► 5 check frames ─►
6 exercises ─► 7 solution audio ─► 8 publish ─► 9 commit
```

## Before starting

- **Read** [course-design.md](course-design.md) (rules) and the block's script in
  `video-scripts/uNN.md`. Only produce a block whose script exists and passes
  `python3 tools/estimate_scripts.py --check`.
- **Access.** Audio is generated by workflows in `gcarrerap/api-access`. The session must have that
  repository attached (in Claude Code on the web: add it to the session) so `gh` can run its
  workflows; check with `gh workflow list --repo gcarrerap/api-access`. If `gh` answers
  `HTTP 403: GitHub access to this repository is not enabled for this session`, attach it
  yourself with the session's add-repo tool (`mcp__claude-code-remote__add_repo`, owner
  `gcarrerap`, repo `api-access`, `access: "push"`; read access is not enough to run workflows),
  clone it once to `../api-access` (the audio steps fetch from there), and check `gh` again. Only
  if the tool is unavailable or refuses, stop and ask the person to attach the repository.
- **Spending.** Every audio run spends Fish Audio credit. When the person asks to produce a block
  (or to continue to the next one), that request authorizes the runs the block needs: one for the
  lesson, one for its solutions. Re-runs for a few bad takes are fine; anything else, ask first.
- **Numbering.** Folders follow the syllabus: `videos/uNN-lTT-<slug>/` for lessons,
  `exercises/uNN-lTT/` for a topic's set (one per topic, shared by its subtopics).

## 1. The script

Already written: `video-scripts/uNN.md`, section `## <number> · <title>`. If something has to
change (a mistake, a better example), change the script first, rerun the estimator, then go on.
Format and pause rules: [video-scripts.md](video-scripts.md).

## 2. `script.json`

```
python3 tools/script_from_md.py 3.4
```

Read the generated blocks once against [audio-production.md §4](audio-production.md): no symbols
in spoken text, numbers spelled out.

## 3. Lesson audio

```
python3 tools/plan_audio.py videos/<video>          # prints the gh command; run it
gh run list --repo gcarrerap/api-access --workflow fish-batch-text-to-speech.yml --limit 1
git -C ../api-access fetch --depth 1 origin audio-temp
python3 tools/plan_audio.py videos/<video> --fetch ../api-access
python3 tools/assemble_audio.py videos/<video>      # narration.mp3 + timeline.json
rm videos/<video>/job.json
```

The real length should be within ~5% of the script's estimate; a bigger gap usually means a
missing pause or a clipped take. Details: [audio-production.md](audio-production.md).

## 4. `video.html`

Write it by hand from the script's `*Screen:*` notes, one `<section class="scene">` per scene,
each change anchored to the word that says it. Copy the head and tail of an existing video
(fonts, `player.css`, the caption/progress/seek/play elements, the scripts). Engine, classes,
shared components and pitfalls: [video-production.md](video-production.md).

## 5. Check the frames

```
python3 tools/render_video.py videos/<video> --stills <t1> <t2> …
```

Take a still in every scene at its busiest moment (just before the scene ends) and during every
pause. The renderer refuses to run if an anchor is wrong. Look at each still and fix:

- nothing overlaps, and nothing enters the bottom ~170 px, where the caption is;
- every element appears when the narration says it, not before;
- each pause shows its question and a countdown ring;
- text is readable (labels in the right color, not hidden behind other marks).

Delete the stills afterwards; they are not committed. The full MP4 render is optional (not
committed).

## 6. Exercises

Each topic has one set, shared by its subtopics; make it once the last subtopic's video is done
([course-design.md](course-design.md), [exercises.md](exercises.md)):

- **10–20 exercises** in the four levels (Warm-up, Tricky, Challenging, Boss level), roughly a
  quarter each, harder ones last.
- Test exactly what the video taught; anything new needs a line in the video first.
- Mix the kinds the topic allows: typed answers (`num`, `expr`) for anything computed, never
  multiple choice for a value; `name`, `multi`, `match` for concepts.
- Every wrong option and every typed known mistake is **one named, real mistake** (forgetting the
  sign, flipping the order), with a `why` that says what went wrong.
- If an answer can't be checked by the existing kinds (an inequality, a point, "no solution"),
  extend `components/answer-check/` and `tools/build_exercises.py` first, with tests in the
  build's checks — never accept text matching.

```
python3 tools/build_exercises.py exercises/<set> --check
python3 tools/build_exercises.py exercises/<set>
```

## 7. Solution audio

The build writes one solution video per exercise (`videos/<set>-exNN/`). Generate their audio in
one batch for the whole set ([exercises.md](exercises.md)), then regenerate their scripts for
review:

```
python3 tools/solution_scripts.py exercises/<set>
```

## 8. Publish

- `index.html`: add the block's `video` and `practice` links in `COURSE`.
- `video-scripts/uNN.md`: set the block's **Status** to `produced`.
- `SYLLABUS.md`: write the real length and "(produced)" next to the block.
- `python3 tools/estimate_scripts.py` to refresh the index table.
- Remove any line of the "Gaps in the current pages" table in [course-design.md](course-design.md)
  that this block closes.

## 9. Commit

One commit per block, pushed to `main` (GitHub Pages publishes it). Pull first: other sessions
work on this repo too.

## Done means

- [ ] Script status `produced`; real length within the 3–10 minute rule.
- [ ] Every scene and pause checked in stills.
- [ ] Exercise set builds with no errors; every exercise has its solution video with audio.
- [ ] Links in `index.html`; syllabus and script index updated.
